# Technical Depth, Problem Solving & Scholarship Portfolio Standards

When presenting software engineering and computational research in academic and scholarship portfolios:

1. **Problem-Solving Scenarios**:
   - Every featured project must explicitly articulate the authentic real-world challenge or friction that justified its creation.
   - Avoid generic descriptions like "A web app that does X"; specify the systemic breakdown, manual time sink, or communication gap it tackled.

2. **Architectural Choices & Technical Depth**:
   - Detail the explicit technical rationale behind architectural patterns (e.g., ASGI asyncpg connection pooling, offline-first IPC event buses, multi-segmented TCP chunking, or localized statistical NLP heuristics).
   - Document technical tradeoffs (e.g., local SQLite vs. remote cloud persistence, edge biometric verification vs. server storage).

3. **Quantified Real-World Impact**:
   - Ground project outcomes in verifiable metrics: median response latency, active user community size, bandwidth acceleration factor, or time savings in research workflows.

4. **Academic & Scholarship Presentation Hierarchy**:
   - **Primary Identity**: The candidate's English name must remain prominent (`H1`) and commanding on the first screen for international committees, professors, and institutional evaluators.
   - **Cultural Accents**: Heritage/calligraphic script (e.g. Urdu Nastaliq) should be rendered in authentic typography (`Gulzar`, `Noto Nastaliq Urdu`) as a refined, tasteful calligraphic seal rather than overpowering the primary academic identity.
   - **Branding Location**: Site-wide brand monikers (e.g., *"A Programmer Chemist's Portfolio"*) belong in the fixed navigation header, keeping the hero centerpiece focused on the candidate's verified academic credentials and research artifacts.
